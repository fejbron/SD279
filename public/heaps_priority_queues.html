Priority Queue ADT

The Priority Queue ADT

A queue where the most urgent item leaves first — not the oldest.

OperationMeaning
insert(x, p)Add item x with priority p
peek()Look at the highest-priority item
extract_min()Remove and return it
len(pq), is_empty()Size checks
Min or max?

In a min-priority queue a smaller number means more urgent. A max-priority queue is the mirror image.

  • Hospital triage — the most critical patient is seen first
  • CPU scheduling — the highest-priority process runs next
  • Dijkstra's algorithm — always expand the closest unvisited vertex (week 10)
  • Huffman coding — repeatedly merge the two least-frequent symbols
  • Event simulation — process the next event in time order
  • Network routers — send urgent packets first

Binary Heap

What Is a Binary Heap?

1 · Shape property

A complete binary tree: every level is full except possibly the last, which fills left to right.

2 · Order property (min-heap)

Every parent is ≤ its children. So the smallest value is always at the root.

  • Siblings are not ordered — 5 can sit left of 8 or right of it
  • A heap is not sorted; only the root is guaranteed
  • Max-heap: parent ≥ children, so the root holds the maximum
a valid min-heap — small numbers are array indices
06 / 29
Binary Heap

Min-Heap vs Max-Heap

min-heap: parent ≤ children · root = min

Use a min-heap for "smallest / earliest / cheapest first".

max-heap: parent ≥ children · root = max

Use a max-heap for "largest / highest score first", and for heap sort.

07 / 29
Binary Heap

Why "Complete" Matters

complete ✓ — last level filled from the left
not complete ✗ — gap before node 5
  • A complete tree with n nodes has height ⌊log₂ n⌋ — never lopsided
  • So sift-up and sift-down walk at most ⌊log₂ n⌋ levels → O(log n)
  • No gaps means the tree packs perfectly into an array — no pointers needed
  • A million items → only about 20 levels
Contrast with a BST

A BST can degrade into a linked list (height n). A heap's shape rule makes that impossible.

Insert

Insert: Append, Then Sift Up

  • Append the new value at the end of the array — the tree stays complete
  • Compare it with its parent at (i - 1) // 2
  • If it is smaller, swap and repeat from the parent's position
  • Stop when the parent is smaller or equal, or we reach the root

At most one swap per level → O(log n).

class MinHeap: def __init__(self): self.a = [] def push(self, x): self.a.append(x) # 1. keep the tree complete self._sift_up(len(self.a) - 1) # 2. restore heap order def _sift_up(self, i): while i > 0: p = (i - 1) // 2 if self.a[p] <= self.a[i]: break # parent is smaller: done self.a[p], self.a[i] = self.a[i], self.a[p] i = p

Extract

Extract-Min: Swap In the Last Leaf, Then Sift Down

  • The minimum is at index 0 — save it to return
  • Move the last element into the root and shrink the array (shape stays complete)
  • Compare it with its children and swap with the smaller child
  • Repeat until both children are larger, or it reaches a leaf

Always swap with the smaller child — swapping with the larger one would put it above a smaller sibling and break the order.

def peek(self): if not self.a: raise IndexError("peek from empty heap") return self.a[0] def pop(self): if not self.a: raise IndexError("pop from empty heap") root = self.a[0] last = self.a.pop() # remove the last leaf if self.a: self.a[0] = last # move it to the root self._sift_down(0) return root def _sift_down(self, i): n = len(self.a) while True: smallest = i l, r = 2 * i + 1, 2 * i + 2 if l < n and self.a[l] < self.a[smallest]: smallest = l if r < n and self.a[r] < self.a[smallest]: smallest = r if smallest == i: return self.a[i], self.a[smallest] = self.a[smallest], self.a[i] i = smallest

Build Heap

Building a Heap: O(n log n) or O(n)?

Naive: n pushes

Push each item one by one: n × O(log n) = O(n log n).

Floyd's bottom-up heapify

Leaves are already heaps. Call sift_down on every internal node from the last one back to the root: O(n).

def heapify(a): n = len(a) for i in range(n // 2 - 1, -1, -1): # last internal node -> root sift_down(a, i, n) def sift_down(a, i, n): while True: smallest, l, r = i, 2 * i + 1, 2 * i + 2 if l < n and a[l] < a[smallest]: smallest = l if r < n and a[r] < a[smallest]: smallest = r if smallest == i: return a[i], a[smallest] = a[smallest], a[i] i = smallest
Level from bottomNodesMax swaps each
0 (leaves)≈ n/20
1≈ n/41
2≈ n/82
h≈ n/2h+1h

Most nodes sit near the bottom and barely move. Σ h·n/2h+1 ≤ n, so the total work is O(n).

Heap Sort

Heap Sort

def heap_sort(a): n = len(a) for i in range(n // 2 - 1, -1, -1): # 1. build a MAX-heap sift_down_max(a, i, n) for end in range(n - 1, 0, -1): a[0], a[end] = a[end], a[0] # 2. max goes to its final spot sift_down_max(a, 0, end) # 3. heap shrinks by one return a def sift_down_max(a, i, n): while True: largest, l, r = i, 2 * i + 1, 2 * i + 2 if l < n and a[l] > a[largest]: largest = l if r < n and a[r] > a[largest]: largest = r if largest == i: return a[i], a[largest] = a[largest], a[i] i = largest print(heap_sort([5, 2, 9, 1, 6])) # [1, 2, 5, 6, 9]

heapq

A Priority Queue Class with Tie-Breaking

import heapq from itertools import count class PriorityQueue: def __init__(self): self._heap = [] self._order = count() # tie-breaker: first come, first served def push(self, item, priority): heapq.heappush(self._heap, (priority, next(self._order), item)) def pop(self): priority, _, item = heapq.heappop(self._heap) return item def __len__(self): return len(self._heap) er = PriorityQueue() er.push("sprained ankle", 3) er.push("cardiac arrest", 1) er.push("broken arm", 2) er.push("chest pain", 1) print([er.pop() for _ in range(len(er))]) # ['cardiac arrest', 'chest pain', 'broken arm', 'sprained ankle']
  • Store (priority, counter, item) tuples
  • Equal priorities fall back to the counter, so they leave in arrival order
  • The item itself is never compared — so it can be any object, even one without <
Without the counter

Two equal priorities would compare the items next. Strings work by accident; dicts or custom objects raise TypeError.

Applications

Top-k Largest in O(n log k)

import heapq def top_k(nums, k): heap = [] # min-heap: k largest so far for x in nums: if len(heap) < k: heapq.heappush(heap, x) elif x > heap[0]: heapq.heapreplace(heap, x) # swap out the smallest return sorted(heap, reverse=True) print(top_k([7, 2, 9, 4, 11, 5, 8], 3)) # [11, 9, 8]
  • Keep a min-heap of size k: its root is the weakest of the current top k
  • A new value only gets in if it beats that root
  • Time O(n log k), space O(k) — great when n is huge and k is small (e.g. top 10 of a million)
Shortcut

heapq.nlargest(3, nums) does the same thing.

Applications

Running Median with Two Heaps

import heapq class RunningMedian: def __init__(self): self.low = [] # max-heap (stored negated): smaller half self.high = [] # min-heap: larger half def add(self, x): heapq.heappush(self.low, -x) heapq.heappush(self.high, -heapq.heappop(self.low)) if len(self.high) > len(self.low): heapq.heappush(self.low, -heapq.heappop(self.high)) def median(self): if len(self.low) > len(self.high): return -self.low[0] return (-self.low[0] + self.high[0]) / 2 rm = RunningMedian() for x in [5, 15, 1, 3]: rm.add(x) print(rm.median(), end=" ") # 5 10.0 5 4.0
  • low holds the smaller half (a max-heap), high the larger half (a min-heap)
  • Every value in low ≤ every value in high; sizes differ by at most one
  • The median is one root, or the average of both
  • Each add is O(log n); each median is O(1)

Complexity Summary

OperationBinary heapWhy

Height of a complete tree = ⌊log₂ n⌋. Every O(log n) above comes from that one fact.

Pitfalls

Common Mistakes

Thinking a heap is sorted

[1, 4, 2, 7, 5, 3] is a valid heap but not sorted. Only the root is guaranteed.

Swapping with the wrong child

Sift-down must swap with the smaller child in a min-heap.

Mixing index formulas

0-based: children 2i+1, 2i+2. 1-based: 2i, 2i+1. Pick one.

Forgetting heapq is a min-heap

For a max-heap push -x and negate again when you pop.

heappop on an unheapified list

Call heapq.heapify(xs) first, or only ever add with heappush.

Comparing payloads

Equal priorities compare the next tuple field. Add a counter so items are never compared.

Key Takeaways

  • A priority queue serves the most urgent item first
  • A binary heap = complete tree + heap order (parent ≤ children)
  • Stored in a plain array: parent (i-1)//2, children 2i+1, 2i+2
  • Insert: append, then sift up — O(log n)
  • Extract-min: move the last leaf to the root, then sift down to the smaller child — O(log n)
  • peek is O(1); building from n items is O(n) with bottom-up heapify
  • Heap sort: O(n log n) always, in place, not stable
  • heapq is a min-heap on a list; negate for max-heaps; add a counter for ties
  • Top-k in O(n log k); running median with two heaps
  • Heaps power Dijkstra, Huffman coding and schedulers
